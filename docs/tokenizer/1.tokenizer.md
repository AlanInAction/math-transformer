## 2. N-gram：从序列统计局部结构

N-gram 从字符或 token 序列中观察连续的局部窗口。

对于序列：

\[
x_1,x_2,\ldots,x_n
\]

N-gram 研究长度为 \(N\) 的局部片段，例如：

\[
(x_i,x_{i+1},\ldots,x_{i+N-1})
\]

语言模型中常见的条件概率形式为：

\[
P(x_i\mid x_{i-N+1},\ldots,x_{i-1})
\]

当前实践中，N-gram 的重要意义不是直接构造最终 Tokenizer，而是建立一个认识：

> 文本中存在大量可以通过局部统计发现的结构。

因此，Tokenizer 的后续构造可以从“字符序列”逐渐走向“更高层的离散符号”。

---

## 3. BPE：从字符空间构造 Vocabulary

### 3.1 初始状态

BPE 从最细粒度的字符开始：

\[
\Sigma=\{\text{字符}\}
\]

例如：

```text
孙悟空大闹天宫
```

初始可以表示为：

```text
孙 / 悟 / 空 / 大 / 闹 / 天 / 宫
```

此时可以理解为：

\[
N=1
\]

即每个字符都是一个 symbol。

---

## 4. BPE 的核心思想

BPE 通过不断寻找高频相邻 symbol pair，并将其合并，从而逐步构造更大的 vocabulary。

基本过程：

\[
\text{字符}
\rightarrow
\text{字符 pair}
\rightarrow
\text{短语}
\rightarrow
\text{更高频的稳定片段}
\]

例如：

```text
孙 / 悟 / 空
↓
孙悟 / 空
↓
孙悟空
```

因此，BPE 可以理解为：

\[
\Sigma^*
\rightarrow
V^*
\]

其中 \(V\) 是通过 merge 逐渐构造出来的 vocabulary。

---

## 5. 频次与概率

BPE 当前实现中使用 cardinality / count 作为 merge 的主要 metric。

设某个候选 symbol 的出现次数为：

\[
C(x)
\]

corpus 总长度为：

\[
N
\]

则经验概率为：

\[
P(x)=\frac{C(x)}{N}
\]

在同一个 corpus、同一个 iteration 中：

\[
N=\text{constant}
\]

因此：

\[
\arg\max_x P(x)
=
\arg\max_x C(x)
\]

所以对于单纯寻找最高频候选 pair：

> 使用整数频次 count 并不会因为概率是小数而产生本质问题。

真正需要注意的是：如果 metric 不再只是简单的频次，而是加入条件概率、归一化或其他因素，那么 count 与 probability 就不能简单等价。

当前实验最终采用 frequency/count 驱动 BPE merge。

## 6. BPE 实现中的几个关键工程问题

### 6.1 Sliding Window

在当前实现中，通过长度为 2 的窗口寻找 pair：

```text
[left, right)
```

并统计：

```python
symbol_merge(symbol_list[left_index:right_index + 1])
```

这对应：

\[
(x_i,x_{i+1})
\]

---

### 6.2 Overlapping Pair

相邻候选 pair 可能发生重叠：

```text
[1, 3)
[2, 4)
```

不能同时 merge，否则会破坏原始序列结构。

因此需要对 merge location 做选择。

当前采用：

```python
if left >= last_right:
    selected.append((left, right))
```

其核心规则是：

> 只有当前候选 pair 与已经选中的 merge 区间不重叠时，才允许继续 merge。

这使得一次 iteration 中的 merge 位置具有明确的非重叠性。

---

### 6.3 Merge Location 的顺序

由于 location 是从左到右扫描得到的，因此可以通过：

\[
left_i \ge right_{i-1}
\]

判断是否发生 overlap。

对于：

```text
[1,3)
[2,4)
```

第二个区间与第一个区间重叠，因此不能再次选择。

## 8. BPE 学到的不是“词”

需要特别注意：

\[
\boxed{
\text{BPE Token} \neq \text{语言学意义上的词}
}
\]

更准确地说：

\[
\boxed{
\text{BPE Token}
=
\text{Corpus 中稳定出现的局部统计结构}
}
\]

因此可能出现：

```text
孙悟空
齐天大圣
花果山
```

这样的语义上很自然的 token，也可能出现：

```text
祖师道你
看时只见
三千六百分罗天大
```

甚至包含换行、段落格式等 corpus 特有结构的 token。

这说明 BPE 学习的是：

\[
\text{统计结构}
\]

而不是预先定义的：

\[
\text{语言学结构}
\]

## 9. 文本清洗与 Tokenizer 的关系

实验过程中还发现，原始文学文本中的：

- 标点符号
- 换行
- 空格
- 段落格式
- 文本元信息

都会参与 BPE 的统计。

例如：

```text
\n\n
```

可能因为高频出现而成为 token 的组成部分。

因此需要根据实验目的决定是否进行 normalization / cleaning。

例如可以基于 Unicode category 对标点进行过滤：

```python
unicodedata.category(ch).startswith("P")
```

这里需要注意布尔条件的含义：

```python
not unicodedata.category(ch).startswith("P")
```

表示：

> 保留“不属于标点”的字符。

如果还需要去掉换行，则需要增加针对 whitespace / newline 的条件，而不是认为 Unicode 的 `P` category 会自动覆盖 `\n`。

因此文本预处理实际上可以看成一个独立函数：

\[
C:\text{Raw Text}\rightarrow\text{Clean Text}
\]

然后：

\[
\text{Raw Text}
\xrightarrow{C}
\text{Clean Text}
\xrightarrow{BPE}
V^*
\]

## 10. 从 Vocabulary 到 Token ID

BPE 完成后得到：

\[
V=\{v_1,v_2,\ldots,v_{|V|}\}
\]

接下来可以为每个 token 分配唯一的整数 ID：

\[
I:V\rightarrow N
\]

其中：

\[
N=\{0,1,\ldots,|V|-1\}
\]

例如：

```text
孙悟空 -> 137
齐天大圣 -> 421
花果山 -> 892
```

这里的 ID 本身没有语义。

`137` 并不意味着 `孙悟空` 与 `齐天大圣` 有某种数学距离。

它首先只是 vocabulary 中的索引。

因此这里可以近似理解为一个离散集合之间的编号映射：

\[
V\leftrightarrow N
\]

## 11. Tokenizer 阶段的整体数学结构

目前已经完成的部分可以概括为：

\[
\boxed{
\text{Text}
\rightarrow
\text{Symbol Sequence}
\rightarrow
\text{BPE}
\rightarrow
V
\rightarrow
N
}
\]

更具体地：

\[
\text{字符序列}
\overset{\text{统计}}
{\longrightarrow}
\text{局部结构}
\overset{\text{merge}}
{\longrightarrow}
\text{Vocabulary}
\overset{\text{index}}
{\longrightarrow}
\text{Token ID}
\]

这里仍然全部属于**离散空间**。

# 12. 下一阶段：Embedding

Tokenizer 到这里实际上已经解决：

> 模型应该认识哪些离散符号？

但神经网络还不能直接对这些离散 ID 进行有意义的几何计算。

因此下一阶段进入：

\[
\boxed{
N\rightarrow\mathbb R^d
}
\]

即 Embedding。

设 vocabulary size 为：

\[
|V|=M
\]

embedding dimension 为：

\[
d
\]

则 embedding 参数可以表示为一个矩阵：

\[
W\in\mathbb R^{M\times d}
\]

对于 token ID \(i\)：

\[
E(i)=W_i
\]

也就是从 embedding matrix 中取出第 \(i\) 行。

因此完整流程变为：

\[
\boxed{
V
\xrightarrow{\text{index}}
N
\xrightarrow{\text{embedding}}
\mathbb R^d
}
\]

或者直接写成：

\[
E:V\rightarrow\mathbb R^d
\]

---

## 13. Token Embedding 与 Position Representation

对于 token 序列：

\[
x_1,x_2,\ldots,x_n
\]

Token embedding 为：

\[
e_i=E(x_i)
\]

但仅有 token embedding 不能自然表达 token 的顺序，因此 Transformer 还需要 position representation。

传统形式可以写为：

\[
h_i=e_i+p_i
\]

其中：

- \(e_i\)：token embedding
- \(p_i\)：position representation
- \(h_i\)：进入 Transformer 的输入表示

因此下一阶段需要重点研究的不是 Position，而是首先理解：

\[
\boxed{
\text{离散 token}
\rightarrow
\text{连续向量空间}
}
\]

以及一个核心问题：

> Embedding Matrix 最初只是参数，为什么经过训练以后会形成有意义的几何结构？
