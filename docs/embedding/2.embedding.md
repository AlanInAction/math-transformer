# 2. Co-occurrence Embedding

## 1. 背景

Tokenizer 阶段完成了：

\[
Corpus \rightarrow Symbol_N \rightarrow Vocabulary
\]

其中：

- `Corpus`：原始文本语料
- `Symbol_N`：经过 BPE 后得到的符号序列
- `Vocabulary`：Symbol 的集合

Tokenizer 解决的是：

> 如何将连续文本划分为离散 Symbol，并建立 Vocabulary。

Embedding 接下来解决的问题是：

> 如何将离散的 Symbol 映射到一个具有几何结构的向量空间。

当前首先采用 **co-occurrence（共现）** 的方式完成这一过程。

---

# 2. 从 Symbol 空间到向量空间

## 2.1 Symbol 本身没有自然的数值结构

对于：

\[
S=\{s_1,s_2,\ldots,s_N\}
\]

Symbol 之间不存在类似自然数、整数、实数的天然序关系。

例如：

\[
s_i < s_j
\]

对于两个 Symbol 通常没有自然意义。

因此不能简单地使用：

\[
d(s_i,s_j)=|i-j|
\]

来衡量 Symbol 之间的关系。

Token ID：

```text
孙悟空 -> 17
菩提祖师 -> 42
````

只是人为建立的索引：

[
ID:V\rightarrow\mathbb N
]

并不意味着：

[
|17-42|
]

能够表示两个 Symbol 的语义距离。

---

# 3. Symbol 的关系来自 Symbol Sequence

虽然 Symbol 本身没有自然的几何结构，但是经过 Tokenizer 后，我们得到了：

[
S=(s_1,s_2,\ldots,s_T)
]

这是一个有序的 Symbol Sequence。

因此可以从 Sequence 中观察 Symbol 之间的**交互关系**。

例如：

```text
孙悟空 在 方寸山 拜 菩提祖师 为师
```

其中：

```text
孙悟空 ↔ 方寸山
孙悟空 ↔ 菩提祖师
菩提祖师 ↔ 方寸山
```

都可以通过文本中的局部共现建立关系。

因此：

[
\boxed{
\text{Symbol 的关系来自 Sequence 中的交互}
}
]

而不是来自 Symbol 本身。

---

# 4. Co-occurrence Matrix

定义 Vocabulary：

[
V={v_1,v_2,\ldots,v_N}
]

构造：

[
C\in\mathbb N^{N\times N}
]

其中：

[
C_{ij}
]

表示 Symbol (v_i) 与 Symbol (v_j) 在文本中的共现次数。

当前实现使用局部 Window。

---

# 5. Window

## 5.1 Window 的意义

假设：

```text
A B C D E
```

对于 `C`，如果：

[
window=3
]

则可以观察：

```text
B C D
A C E
```

即 Symbol 与其局部上下文建立关系。

Window 控制的是：

[
\boxed{
局部性 \leftrightarrow 全局性
}
]

Window 太小：

* 关系更加局部
* 更偏向语法和邻近关系
* 共现矩阵更加稀疏

Window 太大：

* 更多 Symbol 发生共现
* 稀疏性下降
* 局部语义结构可能被全局统计稀释

---

# 6. 当前 Window 定义

当前代码：

```python
window_size = 4
```

实现：

```python
for j in range(window_size - 1):
    right_index = i + (j + 1)
```

因此：

[
window_size=4
]

实际表示：

[
s_i
\rightarrow
s_{i+1},s_{i+2},s_{i+3}
]

也就是说：

> 当前 Symbol 加上右侧 3 个位置。

---

# 7. Direction

Co-occurrence 可以有方向。

## 7.1 单向

如果只统计：

[
s_i\rightarrow s_j
]

则：

[
C_{ij}\neq C_{ji}
]

此时更接近序列中的条件关系：

[
P(s_j|s_i)
]

---

## 7.2 双向

当前实现：

```python
bidirection = True
```

因此同时记录：

[
C_{ij}
]

以及：

[
C_{ji}
]

代码：

```python
set_sparse_matrix_val(
    sparse_co_occurrence_map,
    token_id_i,
    token_id_j
)

if bidirection:
    set_sparse_matrix_val(
        sparse_co_occurrence_map,
        token_id_j,
        token_id_i
    )
```

理论上最终满足：

[
\boxed{
C_{ij}=C_{ji}
}
]

因此：

[
\boxed{
C=C^T
}
]

当前得到的是一个**对称局部共现矩阵**。

---

# 8. Sparse Matrix

实际的：

[
C\in\mathbb N^{N\times N}
]

通常非常稀疏。

大量：

[
C_{ij}=0
]

因此当前没有直接创建：

```python
list[list[int]]
```

而是使用：

```python
sparse_co_occurrence_map = {
    (i, j): count
}
```

表示非零元素。

例如：

```python
{
    (0, 1): 12,
    (0, 5): 3,
    (1, 0): 12,
    (5, 0): 3,
}
```

数学上仍然表示：

[
C\in\mathbb N^{N\times N}
]

只是工程实现采用稀疏存储。

---

# 9. Tuple 作为 Sparse Key

当前使用：

```python
sparse_key = (i, j)
```

而不是：

```python
sparse_key = "{}-{}".format(i, j)
```

原因是：

[
(i,j)
]

天然表示二维矩阵坐标。

因此：

```python
C[(i,j)]
```

可以直接理解为：

[
C_{ij}
]

同时 Python 的 `tuple` 可以作为 `dict` 的 key。

---

# 10. 从 Co-occurrence Matrix 得到 Symbol Vector

对于某个 Symbol (v_i)，取矩阵第 (i) 行：

[
v_i=
(C_{i1},C_{i2},\ldots,C_{iN})
]

得到：

[
\boxed{
v_i\in\mathbb R^N
}
]

这里：

[
N=|V|
]

因此完成了：

[
\boxed{
V\rightarrow\mathbb R^{|V|}
}
]

这就是当前阶段的第一次向量化。

---

# 11. 这个高维空间为什么有意义？

这个空间不是任意构造出来的。

对于：

[
v_i=(C_{i1},C_{i2},\ldots,C_{iN})
]

第 (j) 个维度具有明确含义：

> Symbol (v_i) 与 Vocabulary 中第 (j) 个 Symbol 的共现强度。

因此：

[
\mathbb R^{|V|}
]

虽然维度很高，但是具有很强的可解释性。

例如：

```text
孙悟空
[
    0,
    3,
    17,
    0,
    8,
    ...
]
```

可以理解为：

> “孙悟空”与 Vocabulary 中不同 Symbol 的局部交互统计。

---

# 12. 先升维，再降维

这是当前 TinyGPT Embedding 实验的核心思路。

整个过程：

[
V
\rightarrow
\mathbb R^{|V|}
\rightarrow
\mathbb R^d
]

其中：

### 第一阶段

[
V\rightarrow\mathbb R^{|V|}
]

通过 Co-occurrence 显式构造高维空间。

这个过程：

* 可解释
* 基于统计
* 每个维度具有明确含义
* 保留大量原始 Symbol 交互信息

### 第二阶段

[
\mathbb R^{|V|}
\rightarrow
\mathbb R^d
]

进行降维。

其中：

[
d\ll |V|
]

这一阶段才逐渐接近现代 Embedding 的核心问题：

> 如何用低维稠密向量表示高维 Symbol 关系。

---

# 13. 为什么不能直接从 Vocabulary 得到 R^d？

Vocabulary 本身只是集合：

[
V={v_1,\ldots,v_N}
]

集合中没有天然的几何结构。

如果直接定义：

[
f:V\rightarrow\mathbb R^d
]

当然可以人为指定，但：

> 这个映射本身没有解释来源。

Co-occurrence 提供了中间结构：

[
V
\rightarrow
\text{Symbol Interaction}
\rightarrow
\mathbb R^{|V|}
]

然后再：

[
\mathbb R^{|V|}
\rightarrow
\mathbb R^d
]

因此当前方法提供了一个可解释的中间层。

---

# 14. Cosine Similarity

得到两个 Symbol 的向量：

[
v_A,v_B
]

之后可以使用 Cosine Similarity：

[
\boxed{
\cos(A,B)
=========

\frac{v_A\cdot v_B}
{|v_A||v_B|}
}
]

代码：

```python
def calc_cos_similarity(vecA, vecB):
    dimension = len(vecA)

    dot_res = 0
    dot_a = 0
    dot_b = 0

    for i in range(dimension):
        dot_res += vecA[i] * vecB[i]
        dot_a += vecA[i] * vecA[i]
        dot_b += vecB[i] * vecB[i]

    return dot_res / (
        math.sqrt(dot_a) *
        math.sqrt(dot_b)
    )
```

Cosine Similarity 实际衡量的是两个向量的夹角：

[
\cos\theta
]

因此它关注的是：

> 两个 Symbol 的上下文分布是否相似。

# 15. 《西游记》实验

当前使用《西游记》作为 Corpus。

经过：

```text
Corpus
 ↓
BPE
 ↓
Symbol Sequence
 ↓
Vocabulary
 ↓
Co-occurrence
 ↓
R^|V|
```

然后计算：

```text
孙悟空
```

与：

```text
菩提祖师
```

之间的 Cosine Similarity。

实验得到：

[
\boxed{
\cos(\text{孙悟空},\text{菩提祖师})
\approx0.15
}
]

这个结果具有一定意义。

因为当前完全没有使用：

* 神经网络
* 梯度下降
* Transformer
* 预训练模型
* 语义标签

只是利用：

[
\boxed{
\text{局部共现关系}
}
]

就已经在高维空间中观察到了两个角色之间的非零关系。

---

# 16. 0.15 不代表“15%的语义相似”

需要注意：

[
\cos(A,B)=0.15
]

并不能直接解释为：

> 两个 Symbol 有 15% 的语义相似。

Cosine Similarity 描述的是向量夹角：

[
\theta=\arccos(0.15)
\approx81.4^\circ
]

因此更准确的解释是：

> 两个 Symbol 的上下文向量存在一定程度的正相关。

真正有意义的是**相对比较**。

例如可以比较：

```text
孙悟空 ↔ 菩提祖师
孙悟空 ↔ 唐僧
孙悟空 ↔ 猪八戒
孙悟空 ↔ 沙僧
孙悟空 ↔ 玉皇大帝
```

观察这些 Symbol 在当前高维空间中的相对关系。

---

# 17. Distributional Semantics

当前实验实际上已经体现了一个非常重要的思想：

> 具有相似上下文的 Symbol，往往具有相似的语义。

形式化地：

[
\boxed{
\text{Similar Context}
\Rightarrow
\text{Similar Vector}
}
]

因此：

[
\text{Symbol}
\rightarrow
\text{Context Distribution}
\rightarrow
\text{Vector Geometry}
]

Symbol 原本只是离散集合中的元素。

经过共现统计后，它开始具有：

* 距离
* 方向
* 夹角
* 相似度

于是原本没有几何结构的 Symbol 空间，开始形成一个**关系几何空间**。

[

[

这里特别区分：

对于单个 Symbol：

[
C_{i,:}
\rightarrow
v_i
]

得到：

[
v_i\in\mathbb R^{|V|}
]

最终：

[
\boxed{
V
\rightarrow
\mathbb R^{|V|}
}
]

再进入下一阶段：

[
\boxed{
\mathbb R^{|V|}
\rightarrow
\mathbb R^d
}
]

window_size = 4

# 20. 当前阶段暂不引入的优化

当前目标是理解 Embedding 的基本结构，因此暂时不引入：

* Distance Weighting
* PMI
* PPMI
* TF-IDF
* Matrix Factorization
* SVD
* Neural Embedding
* Gradient Descent

原因不是这些方法不重要，而是希望先完整观察：

[
\boxed{
Symbol
\rightarrow
Co-occurrence
\rightarrow
R^{|V|}
\rightarrow
Similarity
}
]

这个最基础、最可解释的过程。

# 21. 与 GPT 类 Embedding 的关系

当前方法属于：

[
\boxed{
\text{显式统计型 Embedding}
}
]

而 GPT 类模型采用的是另一条路径。

可以粗略表示为：

[
Symbol
\rightarrow
Token ID
\rightarrow
Embedding
\rightarrow
Transformer
\rightarrow
Next\ Token\ Prediction
]

Embedding 参数通过：

[
\text{Loss}
\rightarrow
\text{Gradient}
\rightarrow
\text{Parameter Update}
]

不断调整。

因此：

### 当前方法

[
Symbol
\rightarrow
R^{|V|}
\rightarrow
R^d
]

关系首先被**显式统计出来**。

### GPT 类方法

[
Symbol
\rightarrow
R^d
]

关系主要通过：

[
\boxed{
Next\ Token\ Prediction
+
Gradient\ Descent
}
]

隐式学习。

因此两者最大的区别之一是：

> 当前方法强调显式、可解释的关系构造；GPT 类方法强调通过任务目标隐式学习表示。
